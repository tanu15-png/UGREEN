# Report format

Produce a readable Markdown report in the chat, with an optional approved text save. Use these sections and omit unsupported fields rather than inventing them.

## Scope and coverage

State the project label, authorized scope, confirmed baseline, review date if supplied, included source inventory and actual locations, source roles, and missing or unreadable inputs. Distinguish user-supplied transcripts from audio transcriptions. Describe whether the review is complete for the selected inputs or partial.

## Commitment review

For each commitment show:

1. Baseline promise, responsible party, acceptance criteria, original deadline, and source excerpt/locator.
2. Proposed change and its source; approval evidence and authority status separately. State whether original terms are retained or an approved change is documented.
3. Delivery claim and acceptance claim separately, their dates where stated, and supporting or conflicting sources.
4. One delivery-evidence label from review-rules; explanation and limitations.
5. A concrete follow-up question if unresolved.

Use short entries or a compact table if the client renders tables well. Do not rank people, assign blame, invent precision scores, or calculate completion percentages from incomplete sources.

## Unresolved questions

List material conflicts, missing acceptance evidence, proposed changes without approval, and unreadable sources. Ask questions tied to evidence, such as whether the authorized approver accepted a proposed deadline.

## Limits and save status

State that the report compares supplied records, does not independently verify work, and is not a legal judgment. Report the actual save result only if requested and completed. Otherwise state that the report is shown in chat and has not been saved. Never describe a draft or expected report as NAS runtime evidence.
